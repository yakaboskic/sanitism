The sanitistic method

  1. One manifest. Everything else is generated.Configuration lives in one file; outputs are build products you never hand-edit.
  2. Every number has a source.Values carry the file and command that produced them, and the reader can click through.
  3. Versions are folders. Obviously.Not branches, not copies of the repo, not final_v3_REAL.docx.
  4. One repo per obsession.Papers, proposals and talks about the same project share their figures and numbers.
  5. Same input, same output.Builds are deterministic, so a rebuild never surprises your co-authors.
